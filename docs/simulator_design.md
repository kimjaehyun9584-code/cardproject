# 카드 상품 손익 시뮬레이터 설계서 (v0.4)

> **상태: 범위 확정, 세부 설계 중**
> 합성 고객·거래 데이터(`docs/data_assumptions.md`)를 입력으로, 카드 상품 구조에 따른 손익을 계산합니다.
> 수익·비용 요율은 아직 정하지 않았습니다. **공개 자료로 출처를 확인한 값만** 넣습니다. (5장)

---

## 1. 목적과 범위

### 1.1 목적
- 같은 고객 데이터에 여러 카드 상품 구조를 적용해, **어떤 구조가 어떤 고객층에서 얼마를 남기거나 잃는지** 비교합니다.
- 실제 수익 예측이 아니라 **상품 구조 간 상대 비교**용입니다. (데이터 설계서 6장의 한계를 그대로 따릅니다.)

### 1.2 v1 범위 (2026-10-02 사용자 확정)
| 항목 | 결정 |
|---|---|
| 카드 종류 | **신용카드와 체크카드 상품 모두.** 상품 정의의 `card_kind`로 구분 (v0.2) |
| 손익 항목 | **공헌이익 수준.** 수익: 가맹점수수료·연회비·할부수수료 / 비용: 혜택·조달·대손·승인 처리·모집 비용 |
| 사용 배분 | **주력카드 비율 + 실적 맞추기.** 가입 고객의 신용카드 사용액 중 일정 비율이 이 카드로 오고, 전월실적 구간에 조금 못 미치는 고객 일부는 구간을 채움 |
| 상품 구조 | **할인형 + 적립형.** 두 틀을 JSON으로 정의하고 숫자를 바꿔 여러 안을 비교 |
| 가입 고객 | **세그먼트별 가입률.** 상품마다 세그먼트별 가입률을 지정. 신용카드 상품은 신용카드 보유 고객만 가입 |

### 1.3 v1에서 제외
- 리볼빙, 카드론, 현금서비스, 연체 (데이터 설계서 1.3과 같음)
- 혜택 때문에 신용카드 결제를 체크카드로(또는 반대로) 옮기는 행동. 결제 수단은 합성 데이터의 `payment_type`을 그대로 따름
- 혜택 크기에 따른 가입·이탈 모델(역선택), 경쟁 카드와의 업종별 선택(체리피킹)
- 해외 이용 수수료 수익, 브랜드사 수수료, 제휴사 비용 분담
- 특화형 상품(바우처, 연회비 차등, 특정 업종 특화 혜택)

## 2. 입력

### 2.1 고객·거래 데이터
생성기 결과(`customers.csv`, `transactions.parquet`)를 그대로 씁니다. 이 시뮬레이터가 쓰는 컬럼:

| 데이터 | 컬럼 | 쓰임 |
|---|---|---|
| 고객 | `segment`, `has_credit_card` | 가입 대상 선정 (신용카드 상품은 보유 고객만) |
| 거래 | `payment_type` | 상품의 `card_kind`와 같은 결제 수단의 거래만 이 카드로 배정 |
| 거래 | `category`, `amount`, `txn_datetime` | 혜택·가맹점수수료·월별 집계 |
| 거래 | `excluded_from_performance` | 전월실적 집계에서 제외 |
| 거래 | `installment_months` | 할부수수료·조달 비용 |
| 거래 | `is_cancelled`, `original_txn_id` | 취소 거래는 원거래와 함께 실적·혜택·수수료에서 제외 |

### 2.2 상품 정의 (`config/products/*.json`, v0.4)
실제 카드 조건(5.1)을 그대로 옮길 수 있게 설계했습니다. 상품마다 파일 하나이고, `cardsim/products.py`가 업종 이름·비중 파라미터·한도 이름이 맞는지 검증합니다.

**v1 상품 5종** (모두 뱅크샐러드 원자료 기준, 5.1)
| 파일 | 카드 | 종류 |
|---|---|---|
| `shinhan_mr_life.json` | 신한카드 Mr.Life | 신용, 생활 할인 |
| `samsung_taptap_o.json` | 삼성카드 taptap O (패키지4: 커피전문점 30% + 오픈마켓 7%) | 신용, 생활 할인 |
| `hyundai_zero3_discount.json` | 현대카드 ZERO Edition3 할인형 (0.8%) | 신용, 무실적 할인 |
| `hyundai_zero3_points.json` | 현대카드 ZERO Edition3 포인트형 (1.2%) | 신용, 무실적 적립 |
| `kb_nori2_check.json` | KB국민 노리2 체크카드 | 체크, 생활 할인 |

**상품 항목**
| 항목 | 설명 |
|---|---|
| `card_kind` | `credit` 또는 `check` |
| `annual_fee` | 연회비 (원) |
| `performance.tiers` | 전월실적 구간 하한 목록 (예: `[300000, 500000, 1000000]`). 빈 목록이면 무실적 |
| `performance.exclude_categories` | 이 카드에서 실적에 넣지 않는 업종 (예: 노리2는 후불교통 제외라 `TRANSIT`) |
| `performance.exclude_shares` | 업종 일부만 실적 제외 (예: 노리2의 상하수도 요금) |
| `performance.grace` | 신규 회원 실적 면제: `{"months": 2, "tier": 300000}` = 발급월과 다음 달은 30만 원 구간으로 간주 |
| `benefits` | 혜택 규칙 목록 (아래) |
| `pools` | 한도 이름별 전월실적 구간 → 월 한도. 혜택 여러 개가 같은 한도를 쓰면 **공유 한도** |
| `unmodeled_benefits` | 생성 데이터로 계산할 수 없어 뺀 혜택과 이유. 리포트에 "제외한 혜택"으로 표시 |

**혜택 규칙 (`benefits`의 각 항목)**
| 항목 | 설명 | 실제 예 |
|---|---|---|
| `kind` | `rate`(정률 할인), `points`(적립), `fixed`(건당 정액 할인), `per_liter`(리터당 할인) | Mr.Life 주유 리터당 60원 |
| `rate` / `amount` / `per_liter` | 할인율·적립률, 정액, 리터당 금액 | |
| `match` | 대상 거래: `category`(업종, `*`는 전체), 선택적으로 `merchant_share` 또는 `customer_share`(2.5), `overseas` | 편의점 중 GS25·CU |
| `hours` | 시간대 `[시작, 끝)`. 끝이 시작보다 작으면 자정을 넘김 | `[21, 9]` 밤 9시~아침 9시 |
| `weekdays` | 요일 (0=월 ~ 6=일) | `[5, 6]` 주말 |
| `min_txn_amount` | 건당 최소 결제금액 | 1만 원 이상 시 1천 원 |
| `max_eligible_per_txn` | 1회 할인 대상 금액 상한 | 1회 1만 원까지 (최대 1천 원) |
| `monthly_eligible_cap` | 월 할인 대상 이용금액 상한 | 월 4만 원 이용분까지 |
| `per_day` / `per_month` / `per_year` | 횟수 제한 | 일 1회, 월 5회 |
| `min_tier` | 필요한 전월실적 구간. `null`이면 실적 무관 | 노리2 스타벅스는 실적 무관 |
| `pools` | 이 혜택이 차감하는 한도 목록. 모두 남아 있어야 하고, 가장 적게 남은 한도까지 줌 | Mr.Life 편의점: `convenience` + 통합 `time` |

**계산 규칙**
- 거래는 시간순으로 처리합니다 (Mr.Life 유의사항: "전표 매입 순서대로 할인 적용").
- 혜택 금액 = 정률이면 `min(결제금액, max_eligible_per_txn) × rate`, 정액이면 `amount`, 리터당이면 `결제금액 ÷ 휘발유 가격 × per_liter`. 그다음 월 이용금액 상한, 횟수 제한, 한도 잔액 순으로 줄입니다.
- 한 거래에 혜택 여러 개가 해당하면 모두 적용합니다. 다만 같은 업종에 할인과 적립이 겹치는 경우는 v1 상품에 없습니다.
- 세그먼트별 가입률(`uptake`)과 주력카드 비율(`main_card_share`)은 상품이 아니라 시나리오 설정입니다 (2.4).

### 2.3 손익 가정 (`config/pnl_assumptions.json`)
모든 상품에 공통으로 쓰는 요율입니다. **값은 5장 자료 수집 후 확정합니다.**

| 항목 | 단위 | 쓰임 |
|---|---|---|
| 가맹점수수료율 | 신용·체크별, 업종별 % | 수익 = 사용액 × 수수료율 |
| 할부수수료율 | 할부 개월별 연 % | 수익 = 할부 잔액 × 수수료율 / 12 |
| 조달금리 | 연 % | 비용 = 결제일까지 자금 부담액 × 금리 |
| 이용일 → 결제일 평균 기간 | 일 | 일시불 조달 비용 계산 |
| 대손율 | 사용액 대비 % | 비용 = 사용액 × 대손율 |
| 승인 처리 비용 | 원/건 | 비용 = 승인 건수 × 단가 |
| 모집 비용 | 원/신규 1장 (신용·체크별) | 비용 = 단가 ÷ 안분 개월 (매월) |

**카드 종류별 적용 항목**
| 항목 | 신용카드 | 체크카드 | 이유 |
|---|---|---|---|
| 가맹점수수료 | ✔ | ✔ | 수수료율은 따로 |
| 연회비 | ✔ | ✔ | 상품 정의 값 그대로 (0원 가능) |
| 할부수수료 | ✔ | - | 체크카드는 할부 불가 (데이터 설계서 2.4) |
| 혜택 비용 | ✔ | ✔ | |
| 조달 비용 | ✔ | - | 결제 즉시 계좌에서 출금되어 카드사가 대신 내는 돈이 없음 |
| 대손 비용 | ✔ | - | 잔액 안에서만 결제되어 못 받을 돈이 없음 |
| 승인 처리 | ✔ | ✔ | |
| 모집 비용 | ✔ | ✔ | 단가는 따로 |

### 2.5 가맹점 비중 (`config/merchant_shares.json`, v0.4)
실제 혜택의 상당수가 **특정 가맹점**(스타벅스, GS25·CU, 3대 마트 등)에만 적용되는데, 생성 데이터는 업종까지만 있습니다. 그래서 업종 안에서 해당 가맹점이 차지하는 비중을 파라미터로 둡니다. (사용자 확정, 2026-10-28)

- `level: txn`: 거래마다 해당 여부를 뽑습니다. 같은 고객도 스타벅스와 다른 카페를 섞어 쓰기 때문입니다.
- `level: customer`: 고객마다 한 번 뽑습니다. 통신사, 후불교통 기능 선택처럼 고객이 한 번 정하는 속성입니다.
- 값은 공개 자료(점유율 통계 등)로 출처를 확인해서 넣습니다. 출처를 찾지 못한 비중은 가정값으로 두고 리포트에 표시하며, 결과가 그 값에 얼마나 민감한지 함께 보여줍니다.
- 현재 16개 비중과 휘발유 가격 모두 **미확보**입니다. 자료 수집이 다음 단계입니다.

### 2.4 행동 가정
| 항목 | 설명 | 정할 값 |
|---|---|---|
| 주력카드 비율 | 상품 정의의 `main_card_share`. 고객별로 세그먼트 평균 주변에서 뽑음 | 분산 크기 |
| 실적 맞추기 범위 | 전월실적이 다음 구간에 이 금액 이내로 못 미치면 대상 | 예: 10만 원 |
| 실적 맞추기 확률 | 대상 고객 중 실제로 구간을 채우는 비율 | 예: 50% |
| 실적 맞추기 방법 | 다른 카드로 내던 같은 결제 수단(신용 또는 체크)의 결제를 이 카드로 옮겨 채움 (새 소비는 만들지 않음) | 확정 |

## 3. 계산 절차

12개월(데이터 기간)을 월 단위로 진행합니다.

1. **가입자 선정**: 세그먼트별 가입률로 뽑습니다. 신용카드 상품은 신용카드 보유 고객 중에서만 뽑습니다. 가입 시점은 첫 달로 둡니다. (v1)
2. **거래 배정**: 가입 고객의 거래 중 상품의 카드 종류(신용·체크)와 같은 거래를 주력카드 비율에 따라 이 카드에 배정합니다. 신용카드가 없는 고객은 모든 결제가 체크카드라, 체크카드 상품에서는 전부 대상이 됩니다. 취소 거래는 원거래와 같은 카드로 갑니다.
3. **전월실적**: 전월에 이 카드로 결제한 금액 중 `excluded_from_performance`와 취소 거래를 뺀 합계로 이번 달 구간을 정합니다.
4. **실적 맞추기**: 전월실적이 다음 구간에 조금 못 미치는 고객 일부는, 다른 카드로 가던 같은 결제 수단의 거래를 이 카드로 옮겨 구간을 채웁니다. 옮긴 거래는 이번 달 실적·혜택·수수료에 모두 반영합니다.
5. **혜택 계산**: 이번 달 구간의 한도 안에서 할인 또는 적립을 계산합니다.
6. **수익·비용 계산**: 2.3의 요율로 거래·고객별 수익과 비용을 계산합니다.
7. **집계**: 고객별·세그먼트별·월별 공헌이익.

---

## 4. 출력

`python -m cardsim.simulate --products config/products/a.json config/products/b.json` 형식으로 여러 상품을 한 번에 비교하고, `reports/simulation_report.html`을 만듭니다.

| 표 | 내용 |
|---|---|
| 상품 비교 요약 | 가입자 수, 1인당 월 사용액, 수익·비용 항목별 금액, 공헌이익, 혜택 비용률(혜택 ÷ 가맹점수수료) |
| 세그먼트별 손익 | 세그먼트별 가입자 1인당 공헌이익. 어느 고객층에서 남고 잃는지 |
| 고객 분포 | 공헌이익이 음수인 고객 비율, 상위 10% 고객이 가져가는 혜택 비중 |
| 전월실적 구간 분포 | 월별 구간별 고객 비율, 실적 맞추기로 구간이 올라간 고객 비율 |
| 월별 추이 | 월별 공헌이익 (모집 비용 안분, 계절 계수 영향) |

## 5. 손익 요율 자료 수집 계획

데이터 설계서 4장과 같은 원칙입니다. **기억에 의존한 수치는 쓰지 않고**, 원자료를 `data/reference/`에 저장한 뒤 출처와 함께 씁니다.

| 항목 | 후보 출처 (확인 필요) |
|---|---|
| 가맹점수수료율 (신용·체크) | 금융위원회 가맹점 수수료율 발표, 여신금융협회 가맹점수수료율 공시 |
| 할부수수료율 | 여신금융협회 카드사별 수수료율 비교공시 |
| 조달금리 | 한국은행 ECOS(여신전문금융회사채 금리), 카드사 경영공시 |
| 대손율 | 카드사 경영공시·감사보고서(금융감독원 전자공시) |
