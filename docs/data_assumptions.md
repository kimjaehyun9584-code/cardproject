# 합성 고객·거래 데이터 설계서 (v1.10)

> **상태: 확정 (v1.1), 공개 통계 수집 완료·보정 진행 중**
> 이 문서는 합성 데이터 생성기(`cardsim/`)의 가정을 정의한 설계서입니다. 모든 수치는 `config/params.json`에 그대로 들어 있고, 생성기는 그 파일만 읽습니다.
> 표에 적힌 수치는 모두 **초안 가정값**이며, 아직 공개 통계로 보정되지 않았습니다.
> 각 값은 `4. 공개 통계 보정 계획`에 따라 출처를 확인한 뒤 교체합니다.

---

## 1. 목적과 범위

### 1.1 왜 합성 데이터인가
- 카드사 실제 고객·승인 데이터는 개인(신용)정보라서 외부에서 사용할 수 없습니다.
- 그래서 **공개 통계의 분포를 따르는 가상의 고객과 거래 내역**을 코드로 생성합니다.
- 목표는 "현실의 완벽한 재현"이 아닙니다. **카드 상품 손익 시뮬레이션과 혜택 누수 진단에 필요한 수준의 현실성**을 확보하는 것이 목표입니다.

### 1.2 이 데이터가 쓰이는 곳
| 사용처 | 데이터에 필요한 것 |
|---|---|
| 상품 손익 시뮬레이터 (회사용) | 업종별 사용액, 월 사용액 분포(전월실적 충족 여부), 할부 비중, 해외 결제 비중 |
| 혜택 누수 진단기 (고객용) | 고객 1명의 월별·업종별 거래 내역 |
| 검증 리포트 | 생성 결과와 공개 통계를 비교할 수 있는 집계값 |

### 1.3 범위에서 제외하는 것 (v1)
- 실명, 주민번호, 카드번호, 주소, 전화번호 같은 **식별정보는 아예 생성하지 않습니다.** 고객은 `CUST_000001` 형식의 ID로만 구분합니다.
- 카드론, 리볼빙, 현금서비스, 연체 (v2 이후 검토)
- 법인카드, 가족카드, 선불카드
  - 대학생이 부모 명의 신용카드(가족카드)로 결제한 금액은 **부모 고객의 소비로 간주**하고, 대학생 고객에게는 생성하지 않습니다.

### 1.4 핵심 설계 결정: "카드 한 장의 소비"가 아니라 "고객의 전체 카드 소비"를 생성
- 생성기는 고객이 **어떤 카드를 쓰는지와 무관하게** 한 달 동안 카드로 결제하는 전체 소비를 만듭니다.
- 어떤 소비가 어떤 카드 상품으로 결제되는지는 **시뮬레이터가** 결정합니다.
- 이렇게 나누면 같은 고객 데이터로 여러 카드 상품을 공정하게 비교할 수 있습니다.
- 단, **신용카드와 체크카드는 구분**합니다. 할부 가능 여부와 전월실적 집계 방식이 다르고, 대학생처럼 체크카드 위주로 쓰는 고객층이 있기 때문입니다. (2.4 참고)

> 🔍 **검토 포인트**
> - 세그먼트 개수(7개)가 적절한가? 너무 많으면 보정이 어렵고, 너무 적으면 상품별 차이가 드러나지 않습니다.
> - v1.3: 세그먼트 비중은 행정안전부 2025년 말 20세 이상 인구의 연령 구성(20대 13% / 30대 15% / 40대 17% / 50대 20% / 60대 이상 34%)에 맞춘 값입니다. 고령층도 대부분 카드를 보유하고 있어(한국은행 조사: 60대 이상 최근 1년 사용 신용카드 평균 1.4장) 인구 구성을 그대로 쓰고, 덜 쓰는 정도는 3.3의 결제 횟수로 표현합니다.
> - v0.4부터 **월 사용액은 입력값이 아니라 결과값**입니다. 3.3의 월 결제 횟수와 3.2의 건당 금액을 곱해 계산됩니다.

### 2.3 개인 차이(분산) 가정
- **활동성 계수**(`activity_factor`): 같은 세그먼트 안에서도 결제를 많이 하는 사람과 적게 하는 사람이 있습니다. 고객마다 로그정규분포(평균 1.0, σ = 0.4)에서 뽑아 모든 업종의 월 결제 횟수에 곱합니다.
  - 이유: 음수가 없고, 소수의 헤비 유저가 오른쪽 꼬리를 만들기 때문입니다.
- **업종 취향**: 고객마다 업종별로 감마분포(평균 1.0, shape 2.0) 노이즈를 한 번 더 곱합니다. 같은 사회초년생이어도 카페를 월 5번 가는 사람과 25번 가는 사람이 생깁니다.
- `online_ratio`, `installment_propensity`, `overseas_propensity`, `check_card_ratio`는 세그먼트별 평균을 중심으로 **베타분포**에서 뽑습니다. (0~1 범위 보장)

### 2.4 신용카드·체크카드 구분 (초안)
| 세그먼트 | 본인 신용카드 보유 확률 | 체크카드 사용액 비중 (보유자 기준) | 가정 근거 |
|---|---|---|---|
| S1 대학생 | 8% | 56% | 소득이 없거나 적어 신용카드 발급이 제한적. 신용카드 결제는 주로 부모 명의 가족카드(= 부모 소비로 간주) |
| S2 사회초년생 | 75% | 26.6% | 첫 신용카드 발급 시기. 연말정산 소득공제율 차이로 체크카드 병행 |
| S3 30대 1인가구 | 90% | 19% | |
| S4 양육가구 | 95% | 15.2% | 할부·혜택 목적의 신용카드 선호 |
| S5 중장년 | 95% | 11.4% | |
| S6 자영업 | 90% | 11.4% | |
| S7 고령층 | 80% | 22.8% | 연금 계좌 연동 체크카드 사용 |

- v1.2: 체크카드 사용액 비중은 공개 통계(2025년 4분기 체크카드 승인금액 ÷ 개인카드 승인금액 = 25.4%)에 맞추기 위해 초안값에 0.8을 곱한 값입니다.
- v1.9: S1 대학생을 뺀 전 세그먼트에 0.95를 한 번 더 곱했습니다. (4.8)
- 신용카드 미보유 고객은 모든 거래가 체크카드입니다.
- 체크카드 거래는 **할부 불가**(`installment_months = 0`)로 생성합니다.
- 소비액 자체는 결제 수단과 무관하게 먼저 만들고, 그 뒤에 거래별로 신용·체크를 배정합니다. 결제 수단 때문에 소비 패턴이 바뀌지는 않는다고 단순화합니다.

## 3. 거래 데이터 설계

### 3.1 거래 테이블 스키마 (`transactions.parquet`, `--format csv`로 CSV 출력 가능)
| 컬럼 | 타입 | 설명 | 예시 |
|---|---|---|---|
| `txn_id` | str | 거래 ID | `TXN_0000000001` |
| `customer_id` | str | 고객 ID | `CUST_000123` |
| `txn_datetime` | datetime | 결제 일시 | `2025-03-14 12:31:05` |
| `category` | str | 업종 (3.2 참고) | `CAFE` |
| `amount` | int | 결제 금액(원) | `5800` |
| `channel` | str | `online` / `offline` | `offline` |
| `payment_type` | str | `credit` (신용카드) / `check` (체크카드) | `check` |
| `is_overseas` | bool | 해외 결제 여부 | `false` |
| `installment_months` | int | 할부 개월 (0 = 일시불) | `3` |
| `is_cancelled` | bool | 취소 거래 여부 | `false` |
| `excluded_from_performance` | bool | 전월실적 제외 대상 업종 여부 | `false` |
| `original_txn_id` | str | 취소 거래일 때 원거래 ID (일반 거래는 빈 값) | `TXN_0000000123` |

> `excluded_from_performance`는 공과금, 상품권 등 **많은 카드가 전월실적에서 제외하는 거래**를 표시합니다.
> 실제 제외 기준은 상품마다 다르므로, 최종 판단은 시뮬레이터의 상품 정의(JSON)가 합니다.
> 이 컬럼은 "일반적으로 제외되는 경우가 많은 업종"이라는 참고용 플래그입니다.

- **"건당"은 결제 1회**입니다. 상품 1개 가격도, 한 달 합계도 아닙니다.
  - 카페 4번 = 거래 4건입니다. 한 달 카페 지출은 `건당 금액 × 월 결제 횟수`로 쌓입니다.
  - 온라인쇼핑 1건에는 옷(5~10만 원)뿐 아니라 생필품·식품 소액 주문(1~2만 원), 앱 결제도 섞여 있어 중위값이 옷 가격보다 낮게 잡힙니다. 옷 한 벌(6~8만 원)은 분포의 상위 30% 안쪽에 들어갑니다.
  - 대중교통 1건은 승차 1회입니다. 월 교통비는 월 승차 횟수로 현실성을 맞춥니다. (3.4.1 참고)
- 금액은 **로그정규분포**로 뽑습니다. `분산 σ`가 클수록 금액 폭이 넓습니다. 하위 10%·상위 10% 열은 실제로 생성될 금액의 범위를 보여줍니다. 평균은 중위값보다 높게 나오고, 회식이나 대량 장보기 같은 고액 거래는 꼬리 쪽에서 생성됩니다.
- 업종 중위값은 공개 통계의 **건당 평균 승인금액**으로 보정합니다. (4·5장 참고)
- **업종별 최저 결제금액** (v1.1): 로그정규분포의 아래쪽 끝에서 비현실적인 소액(예: 190원)이 생기지 않도록, 이보다 낮게 뽑힌 금액은 최저 금액으로 올립니다.

  | 업종 | 최저 금액 | 근거 |
  |---|---|---|
  | `TRANSIT` | 1,500원 | 기본요금 수준 (현행 요금표로 확인 필요) |
  | `RESTAURANT` | 3,000원 | 김밥 한 줄 수준 |
  | `CAFE` | 1,700원 | 3.2.2 |
  | `CONVENIENCE`, `MEDICAL`, `ONLINE_SHOP`, `ETC` | 1,000원 | 음료·간식 1개, 약국·앱 소액 결제 |
- **해외 결제**는 별도 업종이 아니라 `is_overseas = true` 플래그로 표현합니다. 주로 `ONLINE_SHOP`(해외직구), `TRAVEL`, `RESTAURANT`에서 발생합니다.
- `TRANSIT`은 실제로는 월 합산 후불 청구가 많지만, v1에서는 건별 거래로 단순화합니다.
  - 대중교통 요금은 기본요금이 정해져 있어 건당 금액을 크게 올릴 수 없습니다. 1,700원은 기본요금에 거리 추가요금을 일부 반영한 값입니다. 기본요금은 보정 단계에서 현행 요금표로 확인합니다.
  - 택시는 `ETC`에 포함합니다. (7장 확정)

#### 3.2.1 세그먼트별 건당 금액 계수 (초안)
같은 업종이어도 대학생과 중장년의 건당 결제액은 다릅니다. 위 중위값에 세그먼트 계수를 곱합니다. 요금이 정해진 `TRANSIT`, `TELECOM`과, 가격대 비율로 차이를 주는 `CAFE`(3.2.2)에는 적용하지 않습니다. `RESTAURANT`(3.2.3)는 일반 식당 가격대에만 적용합니다.

| S1 대학생 | S2 사회초년생 | S3 30대 1인 | S4 양육가구 | S5 중장년 | S6 자영업 | S7 고령층 |
|---|---|---|---|---|---|---|
| 0.65 | 1.0 | 1.1 | 1.15 | 1.15 | 1.2 | 0.9 |

- 예: 온라인쇼핑 중위값은 대학생 29,250원, 30대 1인가구 49,500원입니다.
- 대학생 계수는 v0.4에서 0.8 → 0.65로 낮췄습니다. 소액 결제를 자주 하는 패턴을 반영하지 않으면, 현실적인 결제 횟수를 넣었을 때 월 사용액이 지나치게 커지기 때문입니다.
- **예외: S1 대학생의 `CONVENIENCE`는 0.45를 적용합니다.** (v0.7) 직장인의 편의점 결제는 도시락과 음료 조합이 많지만, 대학생은 삼각김밥·젤리·과자 같은 소액 간식 위주이기 때문입니다.
  - 대학생 편의점 건당 금액: 중위값 약 4,050원, 하위 10% 약 1,900원(삼각김밥 1개 수준), 상위 10% 약 8,700원, 평균 약 4,850원

#### 3.2.2 카페 가격대 혼합 (v0.5)
카페는 저가형 테이크아웃(1,700~2,500원)과 일반 프랜차이즈·개인 카페(4,000~7,000원)로 가격대가 뚜렷이 갈립니다. 하나의 분포에 계수만 곱하면 대학생의 저가 커피가 제대로 표현되지 않아서, **두 가격대를 섞어서** 뽑습니다.

- 저가형: 중위값 2,000원, σ 0.25 (대부분 1,700~2,700원)
- **최저 결제금액 1,700원**: 현재 저가형 매장의 최저 가격대를 반영해, 이보다 낮게 뽑힌 금액은 1,700원으로 올립니다. 그래서 1,700원 결제가 한 금액에 몰려서 생성되며, 이는 저가형 아메리카노 가격대를 표현한 것입니다.
- 일반: 중위값 5,500원, σ 0.45 (두 잔 이상 결제, 디저트 포함 거래가 꼬리 쪽에서 생성)
- 세그먼트 차이는 **저가형 비율**로 줍니다.

#### 3.2.3 음식점 가격대 혼합 (v0.8)
음식점도 카페처럼 가격대가 뚜렷이 갈립니다. 한솥, 봉구스밥버거, 분식, 김밥, 학식 같은 **간편식 한 끼**와, 친구 모임·회식·가족 외식 같은 **일반 식당**입니다. 하나의 분포로 뽑으면 간편식이 하위 10% 근처에만 생성되어, 두 가격대를 섞어서 뽑습니다.

- 세그먼트 차이는 **간편식 비율**로 줍니다. 대학생은 학식과 가성비 한 끼 위주라 75%로 가장 높게 잡았습니다.

- **S7 고령층 (v1.3)**: 자동납부 업종(`TELECOM`, `UTILITY_INS`)을 뺀 모든 업종의 월 결제 횟수에 0.95를 곱했습니다. 한국은행 조사에서 60대 이상의 월 카드 이용 건수는 40대의 0.51배이고, 이 값에서 생성 결과가 0.50배로 맞습니다. (v1.2의 0.75는 0.41배로 너무 낮아 되돌림)
- **20대 소액 결제 (v1.10)**: S1 대학생 `CAFE` 18 → 24회, S2 사회초년생 `CONVENIENCE` 12 → 16회. 한국은행 조사에서 20대의 월 카드 이용 건수는 40대와 같지만(1.00배) 생성 데이터는 0.93배로 늘 낮게 나와, 20대에 흔한 저가 커피·편의점 소액 결제를 늘렸습니다. (4.9)
- `CAFE`: 직장인은 거의 매일 커피를 사는 사람이 많다는 점을 반영해 v0.5에서 전 세그먼트를 올렸습니다. 세그먼트 평균이라 커피를 안 마시는 사람도 섞여 있고, 매일 마시는 사람(월 25~30회)은 2.3의 업종 취향 노이즈로 생성됩니다.
- `UTILITY_INS` (v1.8): 처음 값(0 / 0.7 / 1.5 / 2.5 / 3 / 3 / 2.5회)의 절반입니다. 공과금·보험료 중 일부는 카드가 아니라 계좌 자동이체로 낸다는 점을 반영했습니다. (4.6·4.7)
- `TELECOM` 1.5회: 본인 요금 외에 가족 회선이나 인터넷 요금을 함께 결제하는 경우를 반영합니다. S1 대학생 0.3회는 부모가 대신 내는 경우가 많다는 가정입니다.

> 🔍 **검토 포인트**: 이 설계서에서 가장 중요한 표입니다. "내 주변 대학생·직장인이 한 달에 카페를 몇 번 결제하나"처럼 한 칸씩 생활 경험과 비교해 주세요.

### 3.4 거래 발생 방식
1. **고객별 월 결제 횟수 결정**: `세그먼트 평균 횟수(3.3) × 이용 여부(†) × activity_factor × 업종 취향 노이즈 × 계절 계수`를 기댓값으로 하는 포아송 분포에서 뽑습니다.
2. **건별 금액**: 업종별 로그정규분포(중위값 × 3.2.1 세그먼트 계수)에서 뽑고 10원 단위로 반올림합니다. 카페는 3.2.2의 가격대 혼합과 최저 결제금액 1,700원을, 음식점은 3.2.3의 가격대 혼합을 따릅니다.
3. **일시**: 요일 가중치(주말에 음식점·여행 증가)와 시간대 가중치(카페는 오전·점심, 배달은 저녁)
4. **자동납부 업종**(`TELECOM`, `UTILITY_INS`): 고객별 청구 건수·납부일(1~28일)·기본 금액을 한 번 정하고, 매달 같은 날짜에 기본 금액 ±5% 안팎으로 발생합니다. 활동성 계수와 계절 계수는 적용하지 않습니다. `CULTURE_OTT`는 v1에서 일반 업종처럼 생성합니다.
5. **결제 수단 배정**: 거래별로 신용·체크를 배정합니다. (2.4)

월 사용액과 업종 비중은 입력하지 않습니다. 위 과정을 거친 결과로 정해지고, 그 결과를 3.4.1과 5장에서 공개 통계와 비교합니다.

### 5.1 공개 통계 비교 허용 범위 (v1.4)
처음에는 모든 지표에 ±15%를 일괄 적용했지만, 지표마다 **공개 통계와 정의가 얼마나 같은지**, **시뮬레이터 결과에 얼마나 직접 영향을 주는지**가 달라 지표별로 나눴습니다. 비중 지표는 상대 오차(%)가 아니라 **%p 차이**로 봅니다. 예를 들어 비중이 3%인 항목에서 +15%는 0.45%p에 불과해 너무 엄격하고, 비중이 50%인 항목에서 +15%는 7.5%p나 되어 너무 느슨하기 때문입니다.

| 지표 | 허용 범위 | 이유 |
|---|---|---|
| 1인당 월 카드 사용액 | ±10% | 손익 시뮬레이션의 규모를 결정하는 핵심 지표. 다만 공개 통계는 카드 비이용자와 개인사업자의 사업성 지출을 포함해 정의가 완전히 같지 않음 |
| 1인당 월 결제 건수 (대중교통 제외) | ±10% | 대중교통 승인 방식이 확인되지 않아 제외하고 비교 |
| 건당 평균 결제금액 (대중교통 제외) | ±10% | 혜택 한도·실적 조건 충족 여부에 직접 영향 |
| 체크카드 결제 비중 | ±3%p | 정의가 거의 같고 신용카드 손익에 직접 영향 |
| 온라인 결제 비중 (건수) | ±5%p | 설문 기반 수치라 넓게 |
| 연령 구성 | ±2%p | 인구 통계라 정확하고 세그먼트 비중으로 직접 맞출 수 있음 |
| 연령별 이용 강도 (40대 = 1) | ±0.10 | 설문 기반 비율 |

- 업종 비중과 금액 분포는 **공개 통계의 평균적 모습**만 반영합니다. 실제 고객 개개인의 복잡한 행동(충성 가맹점, 카드 돌려쓰기 등)은 재현하지 않습니다.
- 고객 간 상관관계(가족, 지역)와 경기 변동은 반영하지 않습니다.
- 따라서 시뮬레이터 결과는 **상품 구조를 비교하는 상대 지표**로 해석해야 합니다. 실제 수익 예측으로 쓸 수 없습니다.
